# 감귤 주문 웹

카톡으로 주문 받고 엑셀로 옮기던 일을 대신하는 주문 사이트.

| 주소 | 누가 | 하는 일 |
|---|---|---|
| `/` | 고객 | 주문서 작성 (받는 분 여러 명, 추천인) |
| `/lookup` | 고객 | 이름 + 연락처로 주문 상태·송장번호 확인 |
| `/admin` | 가족 | 입금확인, 상태 변경, 롯데택배 엑셀, 송장 업로드, 추천인 집계, 상품·재고 |

주문 상태: **입금대기 → 입금확인 → 발송중 → 발송완료** (+ 취소)

---

## 처음 설치 (한 번만, 30분 정도)

### 1. Supabase (DB, 무료)
1. https://supabase.com 가입 → New project (Region: Northeast Asia (Seoul))
2. 왼쪽 **SQL Editor** → `supabase/schema.sql` 내용 전체 붙여넣기 → Run
3. **Authentication → Users → Add user** 로 가족 관리자 계정 만들기 (이메일 + 비밀번호)
4. **Authentication → Sign In / Providers** 에서 *Allow new users to sign up* 끄기
   (끄지 않으면 아무나 가입해서 관리자 화면에 들어올 수 있음)
5. **Project Settings → API** 에서 `Project URL`, `anon public` 키 복사

### 2. 내 컴퓨터에서 실행해 보기
```bash
cp .env.example .env.local   # 값 채우기 (Supabase URL/키, 농장명, 계좌, 보존 기간 문구, 농장 주소)
npm install
npm run dev                  # http://localhost:3000
```

### 3. 인터넷에 올리기 (Vercel, 무료)
1. 이 폴더를 GitHub 저장소로 올리기
2. https://vercel.com → Add New Project → 저장소 선택
3. Environment Variables 에 `.env.local` 값 그대로 입력 → Deploy
4. 나온 주소(예: `gyul.vercel.app`)를 카톡으로 보내면 끝

## 매일 쓰는 법

1. **입금 확인**: 관리자 → 주문 → `입금대기` 탭 → 통장 보고 `→ 입금확인` 클릭 (여러 건은 체크 후 한 번에)
2. **송장 뽑기**: `롯데택배 엑셀 (입금확인 전체)` 다운로드 → 알프스에 업로드 → 송장 출력
3. **송장번호 넣기**: 알프스 결과 엑셀을 `송장 엑셀 업로드` 하면 자동으로 들어가고 상태가 `발송중`으로 바뀜
   (한두 건은 표의 송장번호 칸에 직접 입력해도 됨)
4. **배송 끝**: 며칠 뒤 `발송중` 탭에서 전체 선택 → `발송완료`

고객은 `/lookup` 에서 같은 상태와 송장번호를 바로 봄.

### 롯데택배 알프스 연결 (한 번만)
알프스 → 거래처 관리 → 기초 관리 → **파일 형식 관리** 에서 엑셀 열을 아래 순서로 매칭
(시트 `Sheet1`, 1행 열 제목, 2행부터 데이터, A~Q 17열):

| 열 | 제목 | 들어가는 값 |
|---|---|---|
| A | 주문번호 | `1024-1` (주문번호-받는분순서) |
| B | 보내는사람(지정) | 주문한 사람 이름 |
| C | 전화번호1(지정) | 주문한 사람 연락처 |
| D | 전화번호2(지정) | (빈칸) |
| E | 우편번호(지정) | (빈칸) |
| F | 보내는사람주소(지정) | 농장 주소 (`.env.local` 의 `NEXT_PUBLIC_SENDER_ADDRESS`) |
| G | 받는사람 | 받는 분 이름 |
| H | 전화번호1 | 받는 분 연락처 |
| I | 전화번호2 | (빈칸) |
| J | 우편번호 | 받는 분 우편번호 |
| K | 받는사람주소 | 주소 + 상세주소 |
| L | 상품명1 | 상품·재고 탭의 **택배 품목명** (비우면 `노지감귤10k` 처럼 자동) |
| M | 상품상세1 | (빈칸) |
| N | 수량(A타입) | 박스 수 |
| O | 배송메시지 | 배송 메모 |
| P | 운임구분 | (빈칸) |
| Q | 운임 | (빈칸) |

- 보내는 사람은 주문한 사람으로 나가고, 보내는 사람 주소만 농장 주소로 고정
- 한 받는 분에게 상품이 여러 종류면 상품마다 줄이 나뉨
- 주문번호는 `1024-1` (주문번호-받는분순서) 형식. 알프스의 *고객주문번호* 칸에 매칭해 두면
  출력 결과 엑셀에도 그대로 나와서 송장 업로드 때 자동으로 짝이 맞음
- 송장 업로드는 첫 줄 근처에 `주문번호`, `운송장번호`(또는 `송장`)가 들어간 열 제목만 있으면 됨
- `박스별로 한 줄씩` 은 기본으로 켜져 있음 (박스 하나당 한 줄, 수량 1 → 박스마다 송장).
  끄면 상품 하나당 한 줄로 수량이 그대로 나감
- 예전에 설치한 DB라면 SQL Editor 에서 `supabase/002_ship_name.sql` 을 한 번 실행해야 택배 품목명 칸이 생김

### 재고 규칙
- 상품·재고 탭에서 **재고(박스)** 입력
- 남은 박스가 1개라도 있으면 그 주문은 전부 받음 (재고를 넘어도)
- 접수 박스 ≥ 재고 가 되면 그 다음부터 주문서에 **품절**
- 고객에게 남은 수량은 안 보임
- `취소` 하면 그 주문 박스가 다시 풀림
- 동시에 들어온 주문은 DB에서 한 줄로 세워 처리하므로 품절 뒤 주문이 몰래 들어가지 않음

### 한라봉처럼 잠깐만 파는 상품
상품·재고 탭에서 `판매` 체크를 켜고 끄거나, 판매 기간(시작일~종료일)을 넣으면 그 기간에만 주문서에 보임.

### 개인정보 자동 파기
주문서에 안내한 대로(`발송 완료 후 6개월`) 보관 기간이 지난 주문의 개인정보를 매일 새벽 3시(한국시간)에 자동으로 지움.

**기존 DB에 켜기 (한 번만)**
1. Supabase → **SQL Editor** → `supabase/purge.sql` 내용 전체 붙여넣기 → Run
2. 새로 설치하는 경우엔 `schema.sql` 안에 이미 들어 있으므로 따로 실행할 필요 없음
3. 확인: `select * from cron.job;` 에 `purge-personal-data` 가 보이면 됨

**대상**
- `발송완료` 주문: 발송완료 시각(`delivered_at`)으로부터 6개월 지난 것
- `취소` 주문: 주문일로부터 6개월 지난 것

**지워지는 것** (행은 남기고 값만 덮어씀)
- 주문자 이름 → `(파기)`, 연락처 → 빈 값, 입금자명 → 비움
- 받는 분 이름 → `(파기)`, 연락처 → 빈 값, 우편번호·상세주소·배송메모 → 비움, 주소 → `(파기)`

**남는 것** (판매 집계용)
- 주문번호, 상태, 주문·입금·발송 날짜, 금액, 추천인, 상품·수량·단가, 송장번호, 파기 시각(`purged_at`)
- 그래서 추천인 집계와 재고 계산은 파기 후에도 그대로임

관리자 화면에서 파기된 주문은 `개인정보 파기됨 (날짜)` 로 보이고, 롯데택배 엑셀·송장 업로드 대상에서 빠짐.
고객 `/lookup` 에서도 더 이상 조회되지 않음.
기다리지 않고 바로 지우려면 주문 탭의 `보관 기간 지난 개인정보 지금 정리` 버튼.

**보관 기간을 바꾸려면 세 곳을 함께 바꿀 것**
1. cron 의 숫자: SQL Editor 에서
   ```sql
   select cron.unschedule('purge-personal-data');
   select cron.schedule('purge-personal-data', '0 18 * * *', $cron$select public.purge_personal_data(12);$cron$);
   ```
   (`schema.sql`, `purge.sql` 끝부분의 `purge_personal_data(6)` 숫자도 같이 고쳐 두기)
2. `components/admin/Orders.js` 의 지금 정리 버튼 `p_months: 6`
3. `.env.local`(그리고 Vercel 환경변수)의 `NEXT_PUBLIC_PRIVACY_RETENTION` 문구 — 주문서 동의 문구에 그대로 나오므로
   실제 기간과 다르면 안 됨. 바꾼 뒤 Vercel 에서 다시 배포

## 구조
```
app/page.js              고객 주문서
app/lookup/page.js       고객 주문 조회
app/admin/page.js        관리자 (로그인, 탭)
components/admin/*.js    주문 / 추천인 / 상품·재고
lib/excel.js             롯데택배 엑셀 내보내기, 송장 엑셀 읽기
supabase/schema.sql      테이블, 보안 규칙, 주문·조회 함수, 개인정보 파기
supabase/purge.sql       기존 DB용 개인정보 파기 마이그레이션
supabase/002_ship_name.sql  기존 DB용 택배 품목명 컬럼 추가
```
고객 화면은 DB 테이블을 직접 못 읽고, `get_products`, `place_order`, `lookup_orders`,
`get_referrer_names` 함수만 부를 수 있음. 테이블은 로그인한 관리자만 접근.
